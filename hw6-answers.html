(c) A kernel protects its run queue by disabling interrupts on entry to the critical section and enabling them again on exit. (i) Why does this guarantee mutual exclusion on a computer with one processor? (ii) Give two costs of the approach, even on one processor. (iii) The same kernel is moved to a computer with four cores. Describe exactly how two threads can now be in the critical section at the same time.

(i) With one CPU, disabling interrupts prevents timer-preemptive context switching while this thread handles the run queue, provided it does not voluntarily block.
(ii) Interrupt latency delays device and timer handling, hurting responsiveness; an unbounded wait or crash with interrupts off can freeze the system.
(iii) Disabling interrupts is local to a core. T0 on core 0 and T1 on core 1 can each disable its own interrupts and both enter the shared run-queue critical section simultaneously.

(d) (i) What does the call return, and what does it change, when bolt is 0 and when it is 1? Use scheme F from (b) to explain why the read and the write must happen in one instruction. (ii) On a four-core machine, P1 is inside its critical section while P2, P3 and P4 spin. P1 leaves and soon asks to enter again. Which process gets in next, and can P4 wait forever? Which requirement is at risk? (iii) On a one-processor machine with strict priorities, low-priority L holds bolt when high-priority H becomes ready and starts spinning on it. What happens, and why?

(i) For bolt=0, CAS returns 0 and changes bolt atomically to 1; the caller enters. For bolt=1, it returns 1 and leaves bolt at 1; the caller spins. Scheme F fails because separate read/write lets both contenders read 0. Atomic CAS allows only one transition from 0 to 1.
(ii) Any of P2, P3, P4, or a returning P1 may win after release. There is no FIFO order; P4 can lose indefinitely. Requirement 3 (no starvation) is at risk.
(iii) H spins at higher priority, starving L of CPU time to release bolt on a one-processor system. A blocking lock or priority inheritance would let L run and finish.

(iii) Swapping the producer's two signals alone cannot cause this deadlock; both signals are nonblocking, so P never holds s while waiting on e.

(d) (i) What does the single message stand for, and why can at most one process be in its critical section? (ii) What happens if the mailbox starts with two messages, and what if it starts with none? (iii) Why would the scheme fail if receive returned at once, empty-handed, when the box is empty?

(i) The one message is a token granting entry. receive removes it, so everyone else blocks until its holder sends it back on exit.
(ii) Two messages permit two simultaneous entries, violating mutual exclusion. No message leaves everyone blocked indefinitely.

(b) A file is 50 blocks long (blocks 0 to 49). For each allocation method, count disk reads: to reach block 30 on its own (with nothing in memory except the directory entry), on average over all 50 blocks, and to read the whole file in order once.

Contiguous allocation needs a 50-block consecutive run. Free space can exist in scattered runs too small for the file: external fragmentation. Chained and indexed allocation accept scattered free blocks. If the next pointer in chained block 12 is damaged, following the chain from the directory entry cannot reach blocks 13–49. Average chained random access=(1+50)/2=25.5 reads. For indexed random access, each independent request reads the index block and target data block; a full sequential scan reuses the index block once.

(c) A 4 TiB disk is divided into 4 KiB blocks and keeps free space in a bit table (one bit per block). How many blocks does the disk have? How large is the bit table, in bytes and in MiB, what percentage of the disk is that, and how many disk blocks does it fill? A free block list on the empty disk would store each block number as a whole number of bytes: how many bytes does a block number need, and how large would that list be? Finally, why would allocating a block be slow if the OS searched the bit table from the start every time, and what extra table helps?

Disk blocks=(4×2^40)/(4×2^10)=2^30=1,073,741,824. Bit table=2^30 bits / 8=2^27=134,217,728 bytes=128 MiB. Percentage=(2^27/2^42)×100=0.0030517578125%. Disk blocks for bit table=2^27/2^12=32,768.
A block number needs 30 bits, stored as ceil(30/8)=4 bytes. Free list on empty disk=2^30×4=4,294,967,296 bytes=4 GiB, before metadata.
Searching the bit table from the start repeatedly rechecks occupied entries, becoming slower as the disk fills. A summary (hierarchical) bit table marks groups with free bits so full groups can be skipped.
